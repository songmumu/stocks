## 任务：修复信号中心关联指数 CSI 自动分位不显示

### 问题现象
- 用户自选 ETF（513050 中概互联网、159869 游戏ETF）已关联到 CSI 行业指数（H30533、930901）
- 指数参考区（宽基指数区）正确显示 CSI 10年分位：930901=14.6%/极度低估、H30533=22.6%/偏低
- 但 ETF 信号卡片的分位仍显示"暂无分位数据"，action="请先填指数分位"

### 根因分析
三层定位过程：

1. **首次误判**：后端 HTTP 接口返回 `ds=linked` 但 `pct=None`，怀疑 watchlist_signals.py 的 `_load_index_pct` 未调用 `get_index_pct` → 加文件日志确认

2. **定位到函数返回值**：日志显示 `_load_index_pct` 返回 `{'pe_pct': None, 'data_source': 'none', 'note': '无分位'}` → 确认 `get_index_pct` 被调用但走了兜底返回

3. **确认根因**：`get_index_pct` 的 CSI 分支里：
   ```python
   if current_pe is None:
       realtime = fetch_csi_realtime_pe(code)
       current_pe = realtime.get("pe") if realtime else None
   if len(csi_history) >= 30 and current_pe:
   ```
   - 腾讯 ETF（513050/159869）返回 `pe: 0.0`（不是 `None`）
   - `current_pe is None` → False（0.0 is not None）→ `fetch_csi_realtime_pe` 跳过了
   - `current_pe = 0.0` → `and current_pe` → False → 进入兜底返回

### 修复方案
`valuation_service.py` 的 `get_index_pct` CSI 分支改为：
```python
# 只要没拿到有效 PE（>= 0.1），就从 CSI 拉实时 PE
pe_val = current_pe if current_pe and current_pe > 0 else None
if pe_val is None:
    realtime = fetch_csi_realtime_pe(code)
    pe_val = realtime.get("pe") if realtime else None
if len(csi_history) >= 30 and pe_val and pe_val > 0:
    ...
```

### 附带修复
- `_INDEX_NAMES` 补全了 6 个 CSI 指数（H30533/930901/931484/931152/931087/399986）中文名
- 移除 watchlist_signals.py 的文件日志 debug 代码
- 清理 `__pycache__` 确保字节码重新加载

### 教训
- **永远不要假设 `None` 是唯一"无效"的值**：`0.0` 和空字符串同样需要特殊处理
- `__pycache__` 在修改 Python 代码后必须清除，否则 uvicorn 不会加载新字节码
- 跨进程 debug（HTTP 请求 vs 本地 Python 调用）时用文件日志比 print 更可靠
